Security Lab Dashboard & Vulnerability Guide

Below are the implemented controlled lab security weaknesses across OWASP Top 10 categories, complete with outdated component declarations:

A01:2021

Broken Access Control (IDOR & Admin Exposure)

Weakness: Insecure Direct Object Reference on /api/orders/:id and unauthenticated access to /api/admin/users.

Vulnerable Mode: Any logged-in user can view invoice data of Order #1001 or #1003 by changing the URL parameter. Unauthenticated users can access the full admin user directory.

Remediated Mode: Enforces session ownership checks (req.user.id === order.user_id) and restricts /api/admin/users to role admin.

A03:2021

Injection (SQL Injection & Reflected XSS)

Weakness: Raw SQL string concatenation in Product Search (/api/products/search?q=).

Vulnerable Mode: Unsanitized input allows UNION SELECT queries to extract hash data or drop tables.

Remediated Mode: Uses parameterized SQLite queries (WHERE name LIKE ?) and escapes user output.

A05:2021

Security Misconfiguration

Weakness: Missing Security Headers (CSP, X-Frame-Options) & Verbose SQL Stack Trace Exposure.

Vulnerable Mode: Server reveals X-Powered-By: Express/4.18.2 and returns detailed error traces on 500 status codes.

Remediated Mode: Applies Helmet headers, suppresses header disclosure, and serves generic error responses.

A06:2021

Vulnerable and Outdated Components

Outdated Dependencies Documented:

  • jsonwebtoken@8.5.1 (CVE-2022-23529) — Insecure key verification & algorithm none flaw
  • lodash@4.17.11 (CVE-2019-10744) — Prototype Pollution vulnerability
  • ejs@3.1.5 (CVE-2022-29078) — Server-Side Template Injection
A07:2021

Identification & Auth Failures

Weakness: Weak hardcoded JWT secret (secureshop-secret-123) & lack of login rate-limiting.

Remediated Mode: Uses strong environment secret key and validates algorithm integrity.

A09:2021

Security Logging Failures

Weakness: Plaintext login passwords written to server stdout/audit logs during failed login attempts.

Remediated Mode: Passwords redacted as [REDACTED] and audit logs stored securely in database.

How to Scan SecureShop with OWASP ZAP

  1. Target Configuration: Open OWASP ZAP and set the target URL to:
    http://localhost:8080
  2. Phase 1 Scan (Vulnerable Mode): Ensure the Top Security Banner is set to VULNERABLE mode. Run an Automated Quick Scan or Spider + Active Scan in ZAP.
  3. Observe Alerts: OWASP ZAP will discover:
    • Missing Anti-clickjacking Header (X-Frame-Options)
    • Content Security Policy (CSP) Header Not Set
    • Server Leaks Version Information (X-Powered-By)
    • SQL Injection in /api/products/search?q= parameter
    • Absence of Anti-CSRF Tokens
  4. Phase 2 Retest (Remediated Mode): Click the Top Banner toggle switch to enable REMEDIATED MODE. Re-run the OWASP ZAP Active Scan to confirm that high & medium alerts are resolved!
